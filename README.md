# uptime-watch

Внешний мониторинг доменов сервера Cashout Games (173.242.49.22). Раз в 5 минут GitHub Actions проверяет адреса из `checks.txt` и пишет в Telegram:

- **DOWN** — адрес не ответил как ожидалось два раза подряд (с паузой 20 с); повтор раз в час, пока лежит;
- **UP** — адрес снова работает, с длительностью простоя;
- по понедельникам в 09:02 UTC — сводка «мониторинг жив». Нет сводки — значит, не работает сам мониторинг.

Зачем: 18–23.09.2026 `api.playmaxwall.com` и домены Gold Miner Crash почти пять суток отвечали 502, и этого никто не заметил.

## Настройка

1. Репозиторий **публичный** — для публичных репозиториев GitHub Actions бесплатен. Секретов в файлах нет.
2. Settings → Secrets and variables → Actions → New repository secret:
   - `TELEGRAM_BOT_TOKEN` — токен бота;
   - `TELEGRAM_CHAT_ID` — чат, куда писать.
3. Actions → uptime → Run workflow (галочка «тестовое сообщение») — в Telegram должна прийти сводка.

## Ограничения

- Интервал 5 минут — минимум GitHub; при нагрузке запуски опаздывают.
- GitHub выключает расписание после 60 дней без активности в репозитории. Еженедельная сводка коммитит `state.txt` — репозиторий остаётся активным.
- Если стенд за Cloudflare начнёт отвечать 403 на проверки — разрешить в WAF User-Agent `CashoutUptimeWatch/1.0`.

## Добавить адрес

Строка в `checks.txt`: `<хост> <путь> <ожидание>`, где ожидание — точный код (`200`) или `up` (любой ответ, кроме 5xx).
